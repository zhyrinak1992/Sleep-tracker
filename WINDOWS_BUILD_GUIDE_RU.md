# Как получить сборку Sleep Tracker на Windows без Mac

## Что уже подготовлено

В репозитории есть GitHub Actions workflow `.github/workflows/ios-unsigned-build.yml`. Он запускает Flutter-сборку на облачном компьютере macOS, поэтому собственный Mac не нужен. Перед упаковкой workflow выполняет `flutter analyze` и `flutter test`; при ошибках сборка останавливается.

Bundle ID принудительно устанавливается в `ru.sleeptracker.app`. Его нельзя менять между установками и обновлениями.

## Первый запуск сборки

1. Создать приватный репозиторий GitHub и загрузить туда содержимое папки `sleep_tracker_project_v0_14` целиком.
2. Открыть репозиторий на GitHub → вкладка **Actions**.
3. Выбрать **iOS unsigned IPA (AltStore)** → **Run workflow**.
4. Дождаться завершения всех шагов. Красный шаг `Analyze Dart source` или `Run tests` означает, что сначала нужно исправить исходники; не устанавливать такую сборку.
5. В завершившемся запуске открыть блок **Artifacts** и скачать `SleepTracker-unsigned-IPA` на Windows.
6. Распаковать архив артефакта: внутри будет `SleepTracker-unsigned.ipa`.
7. Установить IPA через AltServer/AltStore по обычному сценарию установки собственного IPA. AltStore выполнит подпись на вашем устройстве/компьютере в рамках своей схемы.

## Обновления

При следующем обновлении загружать в тот же GitHub-репозиторий изменённые исходники и запускать тот же workflow. Не удалять приложение с iPhone перед обновлением: это важно для сохранения локальной SQLite-базы. Bundle ID должен оставаться `ru.sleeptracker.app`.

## Важные ограничения текущего исходного проекта

- Это канал сборки и проверки, а не подтверждение готовности всех функций ТЗ.
- Workflow специально запускает анализатор и тесты до сборки. На текущем этапе их результат ещё не известен: он появится только после первого запуска в GitHub Actions.
- В v0.14.0 добавлены HealthKit-фазы/измерения, событийное аудио, SoundAnalysis-классификация, уведомления, семидневное хранение, утренний отчёт и PDF-экспорт. Эти модули включены в исходники, но их фактическая работа ещё не проверена на iPhone.
- Микрофонный поток сохраняет отдельные события, а не непрерывную аудиозапись. iOS может ограничивать фоновый захват; запуск из полностью закрытого приложения не гарантируется.
- Резервная копия включает актуальные таблицы и доступные аудиофайлы. Перед обновлением или переподписанием обязательно создать архив и не удалять установленное приложение.
- iOS-функции, требующие реального устройства (HealthKit, микрофон, фоновые режимы, уведомления), необходимо проверять на iPhone с соответствующими разрешениями.
- Для облачной сборки GitHub Actions могут применяться лимиты GitHub по тарифу и использованию macOS runners.
