# Формат резервной копии v4 (совместимость v1–v4)

Дата: 22 ноября 2026 года.

## Состав архива
- Полный снимок локальной SQLite schema v8: ночные сессии, отметки, заметки, теги, стадии, физиологические измерения, события звука, утренние отчёты, климатические измерения и метаданные приложения.
- Аудиофайлы событий в Base64 внутри JSON. Копирование не заменяет исходные файлы.
- Сводка архива: количество ночей, заметок, аудиособытий, общий размер аудиоданных и количество климатических измерений.

## Проверка целостности на уровне экспорта/импорта
- При экспорте каждый аудиофайл должен существовать и содержать данные. Если файл отсутствует или пуст, создание архива прерывается с понятной ошибкой; неполная копия не выдаётся за успешную.
- При импорте архивов формата v3/v4 отсутствие вложения для события с непустым file_path приводит к отказу до изменения текущей базы. Для истёкших фрагментов с file_path = null сохраняются метаданные без аудиофайла.
- Для архивов формата v1/v2 сохранена обратная совместимость: старые записи аудио без вложенных байтов могут быть пропущены, поскольку исходные файлы в таких архивах отсутствовали.
- Сначала аудиофайлы записываются во временный каталог приложения, затем выполняется транзакционное восстановление SQLite. При ошибке созданные файлы удаляются.
- При полной замене старые аудиофайлы удаляются только после успешного восстановления базы.
- Режим объединения сохраняет локальные записи при совпадении ID.

## Ограничения
- OAuth-токен Яндекса и другие секреты из iOS Keychain не экспортируются. После переноса подключение внешнего сервиса нужно настроить заново.
- Успешное прохождение автоматических тестов не заменяет проверку экспорта и восстановления на физическом iPhone.


## Совместимость версий
- Контейнер резервной копии принимает formatVersion 1, 2, 3 и 4.
- Слой SQLite принимает schemaVersion 3–8. Для старых схем отсутствующие таблицы, появившиеся позднее, нормализуются в пустые разделы до восстановления; климатические измерения добавляются начиная со schemaVersion 6.
- При восстановлении старых схем новые nullable-поля таблиц остаются пустыми, а поля с SQL DEFAULT получают значения по умолчанию текущей схемы. Исторические ID и значения существующих полей не должны переопределяться.
- Формат v4 сохраняет метаданные аудиособытий даже после истечения семидневного срока хранения файлов.
