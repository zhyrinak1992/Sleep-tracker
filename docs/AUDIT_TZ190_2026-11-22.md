## 3. Критические проверки надёжности

1. **ZIP/XML Apple Health.** Импортёр доработан для выбора XML внутри ZIP без фиксированного имени `export.xml`, но новый путь требует проверки на исходном архиве пользователя. Большие архивы, вложенная структура и память устройства — отдельные тесты.
2. **HealthKit.** Текущая ошибка явно сообщает `Missing com.apple.developer.healthkit entitlement`. Это не ошибка разрешения пользователя внутри приложения; пока текущий профиль подписи не содержит требуемое entitlement, прямой доступ HealthKit недоступен. Не обещать исправление сменой приложения для подписи без проверки provisioning profile.
3. **Резервная копия.** В коде текущего формата есть JSON и аудиовложения. Требуется тестировать большие объёмы, свободное место, прерывание операции, контроль целостности, повторный импорт, конфликты и восстановление на другом iPhone. Проверить, что все новые сущности будущих модулей попадают в архив.
4. **Миграции и обновление.** Проверить обновление установленной версии без удаления приложения, сохранность БД/файлов и совместимость Bundle ID `ru.sleeptracker.app`.
5. **Фоновое аудио.** Проверить запуск, блокировку экрана, прерывания, звонки, нехватку разрешений и восстановление. iOS не гарантирует произвольный запуск микрофона из полностью закрытого приложения.
6. **Сборка.** Успешный GitHub Actions IPA подтверждает компиляцию/упаковку, но не работу на устройстве. Для каждого релиза отдельно фиксировать сборку и физические проверки.

## 4. Правило статусов

Для каждого требования в дальнейшей матрице вести четыре независимых отметки:

- **Не начато** — функциональность отсутствует.
- **В исходниках** — код присутствует, но сборка/устройство ещё не подтверждены.
- **Собрано** — соответствующая версия IPA успешно собрана.
- **Проверено на iPhone** — сценарий выполнен на физическом устройстве и результат зафиксирован.

Дополнительно использовать пометки «частично», «заблокировано внешним ограничением» и «требует проверки реализуемости». Не переводить требование в завершённое только по наличию экрана или успешной компиляции.

## 5. Приоритет реализации

1. Надёжность и сохранность: импорт Apple Health ZIP/XML, резервное копирование/восстановление, миграции и обновление без потери истории.
2. Ночная сессия и аудио: жизненный цикл, ошибки микрофона, события, блокировка экрана и восстановление.
3. Утренний отчёт и дневник: полный согласованный состав, редактирование и связность записей.
4. Внешние данные: Яндекс Умный дом, датчики спальни, погода, солнце и Луна.
5. Аналитика: объединение фактических данных сна, физиологии, звуков, погоды и микроклимата; осторожные индивидуальные сравнения.
6. Раздел здоровья, корзина, защита, хранилище, достижения и полные отчёты.
7. Дизайн и финальная проверка всех сценариев на iPhone.

## 6. Неизменяемые ограничения проекта

- Не менять Bundle ID `ru.sleeptracker.app`.
- Не удалять установленное приложение и не очищать пользовательские данные для обновления.
- Перед рискованными экспериментами создавать и проверять резервную копию.
- Не подменять отсутствующие измерения нулями или искусственными значениями.
- Не делать медицинских/причинных выводов из статистических совпадений.
- Не включать отклонённый пользователем пункт 6 ТЗ «Цели и режим сна».
- Яндекс-интеграцию проектировать как чтение данных датчиков; не добавлять управление устройствами и сценарии без отдельного согласования.
- Локальное хранение остаётся базовой архитектурой; обязательное облако не вводить.
