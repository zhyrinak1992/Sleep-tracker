# Яндекс Умный дом в Sleep Tracker

## Назначение и безопасность

Интеграция получает фактические значения температуры и относительной влажности выбранного датчика спальни. Используются только доступные для чтения свойства temperature и humidity. Приложение не управляет устройствами, не запускает сценарии и не меняет настройки умного дома.

Для API устройств используются только:
- GET /v1.0/user/info — комнаты и устройства;
- GET /v1.0/devices/{device_id} — состояние выбранного устройства.

Для авторизации используются OAuth-запросы к oauth.yandex.ru. Запрашивается только scope iot:view; iot:control не запрашивается.

## Авторизация

Реализован OAuth Device Authorization Flow:
1. Приложение запрашивает код устройства через POST /device/code.
2. Пользователь открывает verification_url, входит в нужный аккаунт Яндекса и вводит user_code.
3. Приложение опрашивает POST /token с интервалом, который вернул Яндекс, обрабатывает authorization_pending, slow_down, expired_token и access_denied.
4. Полученные access token, refresh token и срок действия сохраняются в iOS Keychain через flutter_secure_storage с атрибутом ThisDeviceOnly.
5. При HTTP 401 приложение пытается обновить access token с помощью refresh token и повторяет исходный GET-запрос.
6. Локальные токены удаляются только при ответе HTTP 400 с кодом invalid_grant — Яндекс определяет его как неверный или просроченный refresh token. Ошибки конфигурации приложения, ограничения частоты запросов и серверные ошибки не должны стирать сохранённые токены.

Токены не записываются в SQLite, резервные копии, логи или исходный код. Постоянный идентификатор OAuth-устройства хранится в Keychain отдельно от пользовательских данных.

## Получение и хранение измерений

- Из списка устройств выбираются только устройства, у которых есть retrievable-свойства температуры и/или влажности.
- Для каждого свойства требуется фактическое числовое state.value и временная отметка last_updated.
- Время измерения берётся из last_updated, а не из времени получения HTTP-ответа.
- Значения без timestamp, нечисловые, не finite или с недопустимой будущей временной отметкой не сохраняются.
- Устойчивый ID измерения строится из ID датчика, типа показателя и timestamp; повторное получение того же значения не создаёт дубликат.
- Измерения сохраняются локально в climate_samples вместе с датчиком, комнатой, единицей, источником и временем получения. Если активной ночной сессии нет, автоматический сбор не создаёт отдельные измерения вне ночи.

API отдаёт актуальное состояние и timestamp последнего обновления, а не гарантированный архив телеметрии. Если датчик не передал новую временную отметку, приложение не создаёт искусственную точку.

## Опрос и интерфейс

- В настройках пользователь подключает Яндекс, просматривает доступные датчики, выбирает датчик и может вручную запросить свежие показания или отключить интеграцию.
- Комната отображается как свойство выбранного датчика; отдельный фильтр/переключатель комнат пока не реализован.
- Автоматический опрос выполняется не чаще одного раза в 15 минут, если аккаунт подключён, датчик выбран и есть активная ночная сессия.
- Таймер опрашивает датчик во время работы приложения; при активном аудионаблюдении приложение также пытается продолжать опрос в фоне. iOS не гарантирует выполнение такого таймера при заблокированном экране или после приостановки приложения.
- В разделе «Анализ» показывается сводка выбранного датчика за 30 дней: минимум, среднее, максимум, стандартное отклонение, последнее значение, число измерений и покрытие ожидаемого 15-минутного интервала.
- В отчёте отдельной ночи показываются фактические min/mean/max, стандартное отклонение, последнее значение, число точек и покрытие.
- На графике климатической истории разрывы более 45 минут не соединяются линией.

## Ограничения и проверка

Полнота измерений зависит от датчика, его доступности и фактического поведения API. Реальное поведение OAuth и опроса необходимо проверить на физическом iPhone с аккаунтом Яндекса и совместимым датчиком. Нельзя обещать непрерывный сбор при заблокированном экране или закрытом приложении.
