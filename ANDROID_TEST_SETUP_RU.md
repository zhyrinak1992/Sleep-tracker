# Android-тестирование Sleep Tracker на Windows 11

## Назначение

Эта ветка предназначена только для отдельной Android-тестовой конфигурации приложения Sleep Tracker. Она создана от рабочей ветки `feature/unified-achievements` (PR #123), а не от `main`.

Android используется как настольная тестовая среда для проверки интерфейса и обычных сценариев приложения. Это не перевод продукта на Android и не замена iOS-сборки.

## Ограничения

- Не переносить Android-изменения в `main` автоматически.
- Не менять iOS workflow `.github/workflows/ios-unsigned-build.yml` и `codemagic.yaml` в рамках этой задачи.
- Не удалять и не отключать HealthKit, запись звука, геолокацию или другие функции исходного ТЗ.
- Не считать эмулятор подтверждением работы HealthKit или поведения микрофона/геолокации на iPhone.
- Не менять Bundle ID iOS `ru.sleeptracker.app`, версию приложения или номер сборки в рамках подготовки эмулятора.

## Подготовка Windows 11

1. Установить Flutter SDK и добавить каталог `flutter/bin` в PATH.
2. Установить Android Studio и компоненты Android SDK, Android SDK Platform-Tools и Android Emulator.
3. В Android Studio открыть **Tools → Device Manager**, создать виртуальное устройство Pixel (например, Pixel 8) с доступным стабильным образом Android x86_64 и запустить его.
4. В PowerShell проверить окружение:

```powershell
flutter doctor -v
flutter doctor --android-licenses
flutter devices
```

Команда `flutter doctor` должна показать доступную Android toolchain. Лицензии SDK необходимо принять интерактивно.

## Подготовка Android-платформы в этой ветке

В корне клона репозитория, после переключения на `test/android-emulator-windows11`, выполнить:

```powershell
git status --short
flutter create --platforms=android --project-name sleep_tracker .
git status --short
```

Команда создаёт отсутствующий каталог `android/` для существующего Flutter-проекта. Она не должна запускать генерацию Windows-приложения и не предназначена для изменения iOS workflow. Перед фиксацией изменений проверить diff и убедиться, что в нём только Android-платформа и согласованные Android-метаданные.

Затем выполнить:

```powershell
flutter pub get
flutter analyze --no-fatal-infos
flutter test --reporter expanded
flutter build apk --debug
flutter devices
flutter run
```

Для установки готового debug APK на запущенный эмулятор:

```powershell
flutter install
```

Ожидаемый APK: `build\app\outputs\flutter-apk\app-debug.apk`.

## Что проверяем в эмуляторе

- Запуск приложения и отсутствие критических ошибок.
- Главный экран, переходы между разделами и возврат назад.
- Дневник сна: просмотр, добавление и редактирование записей в пределах существующего ТЗ.
- Аналитику, фильтры и отчётные экраны.
- Настройки, сохранение обычных пользовательских параметров.
- Корректность отображения на разных размерах экранов и при перезапуске приложения.

Для локальной проверки не использовать реальные данные пользователя; тестировать на тестовой базе эмулятора.

## Что эмулятор не подтверждает

- HealthKit и фактическую синхронизацию с Apple Health.
- Реальную запись/обработку ночных звуков и ограничения фоновой работы iOS.
- Реальное разрешение геолокации и поведение служб iOS.
- Уведомления и системные сценарии, зависящие от iOS.

Эти проверки остаются отдельным этапом на физическом iPhone. Android-тестирование не заменяет и не меняет iOS-сборку.

## Критерий готовности этапа

Этап считается завершённым после генерации Android-платформы в отдельной ветке, успешных `flutter pub get`, `flutter analyze`, `flutter test`, сборки debug APK и ручного прохождения перечисленных UI-сценариев в Android Emulator. До получения фактических результатов статус сборки — «не проверена».
